# Jay's Blog — Flask Blog with Users

A full-stack blog application built with Flask, featuring user registration, authentication, admin-only post management, and a commenting system with Gravatar avatars.

## Features

- **User authentication** — register, log in, and log out using Flask-Login, with passwords hashed and salted via Werkzeug.
- **Admin-only controls** — the first registered user (id `1`) is the blog admin and is the only one who can create, edit, or delete posts. Enforced both in the UI and via a custom `@admin_only` route decorator.
- **Relational database** — `User`, `BlogPost`, and `Comment` tables linked via SQLAlchemy relationships (`ForeignKey` + `relationship()`), so posts and comments are tied to their authors.
- **Comments** — any logged-in user can comment on a blog post using a CKEditor rich-text field. Anonymous visitors are redirected to log in.
- **Gravatar avatars** — commenter avatars are generated by hashing the user's email and requesting an image from Gravatar, without relying on the unmaintained `flask-gravatar` package.
- **Contact form** — sends a message via Gmail SMTP using `smtplib`.
- **Bootstrap-Flask** — forms rendered with the `render_form()` macro; templates use Start Bootstrap's "Clean Blog" theme.

## Tech stack

## Setup (local development)

1. Clone the repo and create a virtual environment:
   ```
   python -m venv .venv
   source .venv/bin/activate   # Windows: .venv\Scripts\activate
   ```

2. Install dependencies:
   ```
   pip install -r requirements.txt
   ```

3. Create a `.env` file in the project root with:
   ```
   SECRET_KEY=your-secret-key
   MY_EMAIL=your-gmail-address
   MY_PASSWORD=your-gmail-app-password
   FLASK_DEBUG=True
   ```
   > `MY_PASSWORD` must be a [Gmail App Password](https://myaccount.google.com/apppasswords), not your regular account password.

4. Run the app:
   ```
   python main.py
   ```
   Visit `http://127.0.0.1:5002`.

5. Register an account — the **first user to register becomes the admin** (user id `1`) and is the only account that can create, edit, or delete posts.

## Deployment (Render)

1. Push the repo to GitHub.
2. Create a **Web Service** on Render, connected to the repo.
   - Build command: `pip install -r requirements.txt`
   - Start command (from `Procfile`): `gunicorn main:app --bind 0.0.0.0:$PORT`
3. Create a free **PostgreSQL** instance on Render (same region as the web service) and copy its Internal Database URL.
4. Set environment variables on the web service:
   - `SECRET_KEY`
   - `MY_EMAIL`
   - `MY_PASSWORD`
   - `DATABASE_URL` (from the Postgres instance)
   - `FLASK_DEBUG` — omit, or set to `False`
5. Deploy. Free-tier services spin down after inactivity, so the first request after idle time may take ~30–60 seconds to respond.

## Notes

- `debug` is controlled entirely by the `FLASK_DEBUG` environment variable and defaults to `False` — it should never be `True` in a deployed environment.
- On Render's free tier, the filesystem is ephemeral; if you fall back to SQLite instead of Postgres, all data resets on every redeploy or restart.
